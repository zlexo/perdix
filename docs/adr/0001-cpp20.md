# ADR 0001: C++20 as the language

- **Status:** Accepted
- **Date:** 2026-10-02

## Context

A voxel engine lives or dies by memory layout: packed vertex formats, contiguous chunk storage, SIMD-friendly loops, control over every allocation. The graphics ecosystem it depends on (Vulkan, the Vulkan Memory Allocator, the Vulkan Guide and the Khronos samples) is written for C and C++ first. The code must build with Apple Clang (the development machine), GCC and Clang (Linux) and MSVC (Windows).

Rust would also work and would bring memory safety, at the cost of a second learning curve on top of Vulkan and thinner bindings to the libraries above. C would give up the abstractions (templates, RAII, `std::span`) that keep a large engine readable. Zig is promising but young.

## Decision

The engine is written in **C++20** and built with Apple Clang, GCC, Clang and MSVC.

- **No C++ modules.** Toolchain support is uneven, Apple Clang especially. Headers and source files.
- **C++23 library features wait.** Anything newer than C++20 (for example `std::expected`) is only used once all four compilers ship it, or comes from a small local shim.
- **The compiler is chosen explicitly** by the CMake presets, never by whatever `clang++` happens to be first on `PATH`.

## Consequences

- Modern abstractions (concepts, `std::span`, designated initializers, `<bit>`) are available with zero runtime cost.
- Memory safety is our job: sanitizers run in CI, and warnings are errors.
- A later move to C++23 is a new ADR, made when all four compilers support what we would use.
